# kokkai-speaker

国会会議録検索システムの公式APIから発言データを取得し、発言の本文から発言者の名前と肩書きを抜き出すプログラム。

目的は、国会の発言者名を集めることではなく、テキストから役職と氏名を抜き出す方法を作り、その精度を確かめること。発言者名や肩書きはAPIの項目でも取得できるため、それを正解として、本文から抜き出した結果と比べて評価する。

## 結果（2024年3月の参議院の発言100件）

- 名前の正解率：97 / 97 = 100%
- 肩書きの正解率：57 / 97 = 58.8%
- 肩書きの不一致40件は、すべて本文の表記とAPIの定義の違いによるもので、この100件の範囲では抜き出しの誤りは見つからなかった（詳しくは「結果の詳細」）

## 題材の選定理由

以前、アルバイトでWebページから担当者の役職や氏名を抜き出す作業に携わったが、当時は仕組みを十分に理解できていなかった。その作業は、Webページを取得して本文を取り出し、表記ゆれのある本文から役職や氏名を抜き出す、という流れだった。このうち「テキストから役職や氏名を抜き出す」部分を、精度を確かめられる形で自分の手で作り直そうと考え、国会会議録を選んだ。理由は2つある。

- 国立国会図書館が公式にAPIを公開していて、アクセスの間隔など利用のルールが明確なため。個人の練習のためにWebサイトをスクレイピングするよりも、公式に提供されているデータを使うほうが、規約の面で安心だと考えた
- 本文と一緒に、発言者の名前や肩書きが別の項目として返ってくるため、自分の抜き出し結果を答え合わせしながら改善できる

なお、今回はデータの取得に公式APIを使ったため、WebページのHTMLから本文を取り出すスクレイピングの部分は扱っていない。

## 仕組み

### 抜き出し（extract.py）

発言の本文の書き出しには、「○議長（尾辻秀久君）」「○阿達雅志君」のように発言者が書かれている。この部分から、次の手順で名前と肩書きを抜き出す。

1. 本文が「○」で始まらなければ、発言ではないので対象外にする
2. 先頭の「○」を取り除く
3. 最初の全角スペースより前を「発言者の表記」として切り出す
4. 表記に「（」があれば、「（」の前が肩書き、「（」と「君）」の間が名前
5. 「（」がなければ肩書きはなしとし、末尾の「君」を取り除いたものを名前とする

抜き出しに使うのは本文だけで、APIの発言者の項目は使わない。

### 評価（fetch.py）

APIから発言を100件取得し、本文から抜き出した結果と、APIの項目（発言者名 speaker、肩書き speakerPosition）を1件ずつ比べて、名前と肩書きそれぞれの正解率を計算する。

- 「○」で始まらないデータ（会議録情報）は評価から除外する。発言が誤って除外されていないか確かめるため、除外したデータも表示する
- 肩書きの不一致は、パターンごとに自動で数える

## 使い方

必要な環境：Python 3.9以上（removesuffix を使っているため）

```
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python extract.py     # 抜き出し処理のテスト
python fetch.py       # APIから100件取得して評価
```

## 結果の詳細

### 改善前

名前と肩書きの両方が一致した場合だけを正解として数えていた。正解率は 57 / 97 = 58.8% だった。

### 改善後

不一致を見ると、名前はすべて一致していて、ずれていたのは肩書きだけだった。そこで名前と肩書きを別々に評価し、肩書きの不一致をパターン分けした。

- 名前の正解率：97 / 97 = 100%
- 肩書きの正解率：57 / 97 = 58.8%
- 肩書きの不一致40件の内訳
  - 委員長の扱いの違い（13件）：本文は「委員長」、APIは肩書きなし
  - 正式名称に含まれる（15件）：本文の「副大臣」が、APIの「国土交通副大臣・内閣府副大臣・復興副大臣」に含まれる、など
  - その他（12件）：本文は「国務大臣」「政府参考人」、APIは「外務大臣」「外務省大臣官房審議官」などの具体的な役職名

どのパターンも、本文に書かれている肩書きと、APIに記録されている肩書きの定義の違いによるもので、抜き出し処理の誤りではなかった。なお、改善後も肩書きの正解率の数字自体は変わっていない。変わったのは、本当の誤りと定義の違いを分けて評価できるようになった点である。

## わかったこと

- 正解として使っていたAPIの項目にも、独自のルールがあった。数字だけを見ると58.8%だが、不一致の中身を見ると、抜き出しの誤りではないことがわかった
- 評価から除外したデータ（3件）は、すべて会議録情報（会議の冒頭部分）だった。除外の中身を確認しないと、正解率が実際より高く見えてしまう恐れがある
- 全角の「（」と半角の「(」は別の文字として扱われ、半角では分割できないことを、対話モードで試して確かめた
- APIの具体的な役職名は、会議録の冒頭にある出席者一覧などから付けられていると考えられる（未確認）

### 学んだ技術

- 仮想環境（venv）の作成と有効化、requirements.txt
- requests によるAPIからのデータ取得と、JSONの扱い
- 文字列の操作（startswith、split、removesuffix）
- 関数の作成、ファイル間の import、`if __name__ == "__main__":`
- APIには1回あたりの取得件数の上限がある（このAPIは100件まで）

## 開発の進め方

Pythonの経験がほとんどない状態から、AI（Claude）に解説やヒントをもらいながら進めた。APIからの取得や評価の部分はAIにコード例を出してもらい、自分で打ち込んで一行ずつ意味を確認した。発言者の書き方の規則はデータを観察してAIと一緒に整理し、肩書きと名前を分ける処理はヒントをもとに自分で書いた。不一致の原因の分析も、結果を見ながらAIと一緒に行った。エラーが出たときは、エラーメッセージの意味を教わりながら、自分で原因を探して直した。

## 今後の課題

- 衆議院での検証（発言者の書き方が違う可能性がある）
- 別の時期や委員会も含めて、件数を増やした検証
- 会議録情報の出席者一覧から、具体的な役職名を補う。本文には「国務大臣」としか書かれていないため、出席者一覧を読み込んで「上川陽子さんは外務大臣」のように突き合わせる。新しい関数の追加が必要になる
- 今回扱わなかった、HTMLから本文を取り出すスクレイピングの部分を、スクレイピングの練習用に公開されているサイトで、BeautifulSoupを使って試す
- 正規表現を使った抜き出しも試し、今の方法と比べる
